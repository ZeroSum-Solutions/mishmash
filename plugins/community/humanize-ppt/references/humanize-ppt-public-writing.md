# Humanize PPT public writing / propagation notes

Use when drafting public-facing articles, scripts, README copy, or launch posts about Humanize PPT.

## Core positioning

Humanize PPT is not a fixed bundle of 4 PPT Skills and not a slide renderer. It is a PPT outline/director layer that adapts to different upstream outline-producing Skills and turns their outputs into a cleaner production contract for downstream HTML PPT/rendering/video tools.

Preferred phrasing:

- `Humanize PPT adapts to the outlines different Skills hand over and shapes them into a contract that is better suited for PPT production.`
- `You can recommend pairing it with guizang, Zara, other HTML PPT Skills, Frontend Design, HyperFrames, and more — but those are suggested pairings, not product boundaries.`
- `It works like a director/editor: it removes the model's scratch paper, keeps the judgment, translates features into scenes, and turns the outline into a narrative the audience can follow.`

Avoid:

- `Humanize PPT only supports / is bound to these 4 Skills.`
- `Humanize PPT is just a PPT generator.`
- `Writing the recommended-Skill list as the product definition.`

## Article angle that worked

Two-article split:

1. **WorkBuddy / Agent Teams / OPC angle**
   - Open with a concrete scene, e.g. "a few AI colleagues just got hired by a big company."
   - Use the WorkBuddy expert-team framing to explain the one-person company as "one person orchestrating an AI team," not "one person grinding through all the work alone."
   - Mention the real chain only as proof: outline → HTML PPT → speaker notes → screenshots → HyperFrames video → install video script/TTS.
   - End on: "running a one-person company really is getting simpler — anyone can do it."

2. **Humanize PPT product angle**
   - Open with the concrete pain: language models put useless thinking process or draft notes into PPT pages.
   - Explain Humanize PPT as the middle layer between many Skills and renderers.
   - Use a real deck case to show how it turns features into scenes: Agent Browser = "a web page is a live scene, not text"; Office docs = "the real time sink is the file format"; Web Search = "for anything recent, search first, then answer."
   - Emphasize that AI-generated content often has too much content but not enough human judgment.

## Style reminders for public drafts

- Keep the narrative concrete and first-person. Do not turn Skill releases into feature-list posts.
- Do not overuse mechanical sections like "case one, case two, case three."
- Do not add mechanical spaces around product/model names unless the spaces are part of the name itself.
- Put recommended pairings after the positioning is clear, so readers do not mistake examples for limits.
