## Mandate (verbatim intent)

Execute the seven docket items as **phases**. Each phase runs an implement → test →
implement loop until green, then **lands and pushes** (feature branch → `zs-land`
squash-merge) before the next phase starts. Delegate to the most suitable models;
the orchestrator does final passes. External model (GPT‑5.6 via codex) audits this
PRD before execution. Evaluations (verification commands) are defined per phase and
must be met with captured proof. Do not stop until all seven are done.

## Global constraints

- **AGENTS.md governs.** Red spec before source change, every phase. Web strings go
  through `i18n/types.ts` + `locales/en.ts`. Feature work touching daemon HTTP API
  gets a matching `od` CLI surface in the same PR (dual-track rule).
- **Scope discipline (/goal §4).** Only what a phase's criteria require. No hygiene
  extras. Out of scope everywhere: renaming internal identifiers (`@open-design/*`
  package names, storage keys other than the P6 accent key), upstream-sync tooling,
  Electron workflows (deleted), metering, Tier‑4 items.
- **Landing.** One phase = one feature branch = one squash-merge via `~/bin/zs-land`
  after its verification criteria pass locally. No direct pushes to `main`. If CI
  fails post-push, fixing that PR preempts the next phase.
- **Baseline gates for every phase:** `pnpm typecheck` and `pnpm guard` exit 0, plus
  the phase's own criteria below. From P2 onward, the daemon suite gate added in P2
  must also be green.
