# Decision: unpark and land the remaining wave branches (2026-08-03)

**Status:** Accepted
**Date:** 2026-08-03
**Resolves:** the parking dispositions recorded in PR #24 (founder rulings for
W1/W9as/W10a/W10b/W10c/W10e/W10f), PR #27 (parked W10a+W10b), PR #28 (parked
W9-agent-spawn), and PR #29 (parked W10c).

## The question

By 2026-08-03, `main` had 39 merged PRs and zero open PRs, but 14 local
branches remained unmerged: three `wt/*` branches and eleven `feat/w*` wave
branches. The `wt/*` branches (`wt/home-restructure`, `wt/kit-starter`,
`wt/scroll-film`) were already landed content-wise via PR #36's squash merge —
`apps/daemon/src/copy-directory.ts`,
`plugins/_official/scenarios/od-scroll-film`, and
`apps/web/src/components/FeaturedTemplatesRow.tsx` all exist on `main` — so
they needed no action beyond confirming that.

The eleven `feat/w*` branches were a mix of: waves whose PRD-plus-verifier
pairs had been deliberately parked (docs-only, no implementation) pending a
founder call, and two branches suspected of being fully superseded by a
later, differently-named branch that already landed. Devin's 2026-08-03
instruction was explicit: unpark everything parked, land the remaining wave
branches, and get `main` current.

## Ruling: **unpark and merge, with two branches investigated for supersession**

Devin unparked all founder rulings from PR #24/#27/#28/#29. Per his
instruction, every remaining `feat/w*` branch's *current* state was merged as-is,
except where investigation showed a branch added nothing beyond a
successor that had already landed.

## Superseded-suspect investigation

Two branches were flagged for possible full supersession by a differently-
named branch that already landed, and were investigated before merging
anything:

### `feat/w9-ingest-impl` — not superseded, merged

PR #20 (`feat/w9-ingest-tranche`, squashed onto `main` as `4fe0f677b7`) landed
only `docs/plans/waves/W9-ingest-tranche.md` and
`scripts/waves/verify-w9-ingest.ts` (the PRD and verifier) — zero
implementation files. `feat/w9-ingest-impl`'s actual C9-4/C9-6 implementation
(the byte-volume accounting and rate limiters above) has no equivalent
anywhere on `main`: `clipperIngestByteVolume` had zero hits in the codebase
and none of its ~19 new test files existed. This branch's content was real,
additional, unlanded work, not a duplicate — it was merged.

### `feat/w1-routing-truth` — fully superseded, skipped

PR #30 (`feat/w1-routing-truth-v2`, squashed onto `main` as `1839c333bb`)
landed the model-routing-truth feature (`apps/daemon/src/routes/usage.ts`,
`apps/daemon/src/runtimes/usage-tracking.ts`,
`packages/contracts/src/api/model-routing.ts`, `AssistantMessage.tsx`,
`EntryShell.tsx`, `scripts/waves/verify-w1.ts`, and associated tests).
Diffing every file `feat/w1-routing-truth` touches against that squash
commit shows they are **byte-identical** for every file except
`scripts/waves/verify-w1.ts` — and the reverse: `main`'s current version of
each file differs from `feat/w1-routing-truth` only because `main` moved on
independently afterward (confirmed by diffing the squash commit against
current `main`, which reproduces the same deltas). For `verify-w1.ts`
specifically, `feat/w1-routing-truth` is *missing* a "GATE AMENDMENT"
(a `waitForContainerText` race-condition fix for the model-routing badge's
async render) that the landed v2 branch added afterward — i.e. the original
branch is stale relative to what shipped, not ahead of it. `feat/w1-routing-truth`
adds nothing beyond what `main` already has. It was **not** merged; no
merge was attempted since the file-level evidence was conclusive.
